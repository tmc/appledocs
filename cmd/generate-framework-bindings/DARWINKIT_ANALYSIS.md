## Overview

DarwinKit uses a consistent pattern for generating Go bindings to Objective-C frameworks. The bindings are generated per-class in individual files and follow strict conventions for type safety, memory management, and runtime integration.

**Key Repository Structure:**
- `/objc/` - Core Objective-C runtime integration (purego-based)
- `/macos/appkit/` - AppKit framework bindings (451+ class files)
- `/macos/foundation/` - Foundation framework bindings (311+ class files)
- `/macos/coregraphics/` - CoreGraphics framework bindings
- `/macos/{framework}/` - Other framework bindings

## File Organization

### One File Per Class Pattern

Each Objective-C class gets its own `.gen.go` file:

```
macos/appkit/
  ├── button.gen.go           # NSButton
  ├── window.gen.go           # NSWindow
  ├── application.gen.go      # NSApplication
  └── view.gen.go             # NSView
```

### File Naming Convention

Files are named using snake_case derived from the class name:
- `NSButton` → `button.gen.go`
- `NSTableView` → `table_view.gen.go`
- `NSApplicationDelegate` → `application_delegate.gen.go`

### Additional Files

- `protocols.gen.go` - Protocol registration in `init()`
- `enumtypes.gen.go` - Enum type definitions
- `aliastypes.gen.go` - Type aliases
- `doc.gen.go` - Package documentation
- `{framework}_structs.go` - Custom struct definitions
- `{framework}_custom.go` - Manual implementations

## Class Structure

### Complete Class Definition Pattern

Every class file follows this structure:

```go
// Code generated by DarwinKit. DO NOT EDIT.

package appkit

import (
    "unsafe"
    "github.com/progrium/darwinkit/macos/foundation"
    "github.com/progrium/darwinkit/objc"
)

// The class instance for the [Button] class.
var ButtonClass _ButtonClass

func init() {
    ButtonClass = _ButtonClass{objc.GetClass("NSButton")}
}

type _ButtonClass struct {
    objc.Class
}

// An interface definition for the [Button] class.
type IButton interface {
    IControl
    // Method declarations...
    Title() string
    SetTitle(value string)
    // ...
}

// A control that defines an area on the screen... [Full Topic]
//
// [Full Topic]: https://developer.apple.com/documentation/appkit/nsbutton?language=objc
type Button struct {
    Control
}

func ButtonFrom(ptr unsafe.Pointer) Button {
    return Button{
        Control: ControlFrom(ptr),
    }
}

// Constructor and method implementations follow...
```

### Key Components

1. **Global Class Variable**: `var ButtonClass _ButtonClass`
   - Initialized in `init()` via `objc.GetClass("NSButton")`
   - Used for all class methods and constructors

2. **Private Class Type**: `type _ButtonClass struct { objc.Class }`
   - Embeds `objc.Class` for runtime operations
   - Methods on this type are class methods

3. **Interface Type**: `type IButton interface`
   - Defines the complete API contract
   - Embeds parent interface (e.g., `IControl`)
   - All methods, properties, and operations

4. **Concrete Type**: `type Button struct`
   - Embeds parent struct (e.g., `Control`)
   - Provides concrete implementation
   - Memory layout matches Objective-C runtime

5. **From Constructor**: `func ButtonFrom(ptr unsafe.Pointer) Button`
   - Wraps existing Objective-C instance
   - Calls parent's From constructor

## Interface Design

### Interface Naming Convention

Interfaces are prefixed with `I`:
- `NSButton` → `IButton`
- `NSString` → `IString`
- `NSApplicationDelegate` → `PApplicationDelegate` (protocols use `P`)

### Interface Embedding

Interfaces follow the inheritance hierarchy:

```go
type IButton interface {
    IControl  // Embeds parent interface
    // Button-specific methods...
}

type IControl interface {
    IView  // Further up the hierarchy
    // Control-specific methods...
}

type IView interface {
    IResponder
    // View-specific methods...
}
```

### Method Signatures in Interfaces

Methods in interfaces use the interface types for parameters:

```go
type IButton interface {
    SetImage(value IImage)              // Takes interface
    SetSound(value ISound)              // Takes interface
    SetSymbolConfiguration(value IImageSymbolConfiguration)
}
```

## Constructor Patterns

### 1. Alloc + Init Pattern

```go
func (bc _ButtonClass) Alloc() Button {
    rv := objc.Call[Button](bc, objc.Sel("alloc"))
    return rv
}

func (b_ Button) Init() Button {
    rv := objc.Call[Button](b_, objc.Sel("init"))
    return rv
}
```

### 2. New Constructor

```go
func (bc _ButtonClass) New() Button {
    rv := objc.Call[Button](bc, objc.Sel("new"))
    rv.Autorelease()
    return rv
}

func NewButton() Button {
    return ButtonClass.New()
}
```

**Key Points:**
- `New()` automatically calls `Autorelease()`
- Standalone `NewButton()` function provided for convenience
- Returns fully initialized instance

### 3. Custom Initializers

```go
func (b_ Button) InitWithFrame(frameRect foundation.Rect) Button {
    rv := objc.Call[Button](b_, objc.Sel("initWithFrame:"), frameRect)
    return rv
}

func NewButtonWithFrame(frameRect foundation.Rect) Button {
    instance := ButtonClass.Alloc().InitWithFrame(frameRect)
    instance.Autorelease()
    return instance
}
```

**Pattern:**
- Method on instance type: `InitWithFrame`
- Convenience function: `NewButtonWithFrame`
- Convenience function handles Alloc + Init + Autorelease

### 4. Factory Methods (Class Methods)

```go
func (bc _ButtonClass) ButtonWithTitleTargetAction(
    title string, target objc.IObject, action objc.Selector) Button {
    rv := objc.Call[Button](bc, objc.Sel("buttonWithTitle:target:action:"),
        title, target, action)
    return rv
}

func Button_ButtonWithTitleTargetAction(
    title string, target objc.IObject, action objc.Selector) Button {
    return ButtonClass.ButtonWithTitleTargetAction(title, target, action)
}
```

**Pattern:**
- Method on class type: `ButtonWithTitle...`
- Module-level function: `Button_ButtonWithTitle...`
- Returns autoreleased instance

## Method Signatures

### Instance Method Pattern

```go
func (b_ Button) Title() string {
    rv := objc.Call[string](b_, objc.Sel("title"))
    return rv
}

func (b_ Button) SetTitle(value string) {
    objc.Call[objc.Void](b_, objc.Sel("setTitle:"), value)
}
```

**Key Aspects:**
1. Receiver uses underscore suffix: `b_`
2. Uses `objc.Call[T]` for type-safe runtime calls
3. Selector created via `objc.Sel("methodName")`
4. Void methods use `objc.Call[objc.Void]`

### Method Name Transformation

Objective-C → Go transformation:
- `-[NSButton setTitle:]` → `SetTitle(value string)`
- `-[NSButton initWithFrame:]` → `InitWithFrame(frameRect Rect)`
- `-[NSButton setImage:]` → `SetImage(value IImage)`
- `+[NSButton buttonWithTitle:target:action:]` → `ButtonWithTitleTargetAction(...)`

**Rules:**
- Remove colons from selector
- Convert to PascalCase
- Multiple parameter methods concatenate all parts
- First word of each parameter part is capitalized

### Parameter Type Handling

```go
// Primitive types pass directly
func (b_ Button) SetIntValue(value int) {
    objc.Call[objc.Void](b_, objc.Sel("setIntValue:"), value)
}

// Structs pass directly (purego handles ABI)
func (b_ Button) SetFrame(frameRect foundation.Rect) {
    objc.Call[objc.Void](b_, objc.Sel("setFrame:"), frameRect)
}

// Objects use interface types
func (b_ Button) SetImage(value IImage) {
    objc.Call[objc.Void](b_, objc.Sel("setImage:"), value)
}

// Strings automatically converted
func (b_ Button) SetTitle(value string) {
    objc.Call[objc.Void](b_, objc.Sel("setTitle:"), value)
}

// Arrays automatically converted
func (b_ Button) SetArray(value []objc.IObject) {
    objc.Call[objc.Void](b_, objc.Sel("setArray:"), value)
}
```

## Property Accessors

### Property Pattern

Properties generate getter and setter methods:

```go
// Getter
func (b_ Button) Title() string {
    rv := objc.Call[string](b_, objc.Sel("title"))
    return rv
}

// Setter
func (b_ Button) SetTitle(value string) {
    objc.Call[objc.Void](b_, objc.Sel("setTitle:"), value)
}
```

### Boolean Properties

Boolean properties use `Is` prefix:

```go
// @property (getter=isEnabled) BOOL enabled;
func (b_ Button) IsEnabled() bool {
    rv := objc.Call[bool](b_, objc.Sel("isEnabled"))
    return rv
}

func (b_ Button) SetEnabled(value bool) {
    objc.Call[objc.Void](b_, objc.Sel("setEnabled:"), value)
}
```

### Read-Only Properties

Read-only properties only have getters:

```go
func (b_ Button) FirstResponder() Responder {
    rv := objc.Call[Responder](b_, objc.Sel("firstResponder"))
    return rv
}
// No setter generated
```

## Protocol/Delegate Patterns

### Protocol Interface Definition

Protocols use `P` prefix and define optional methods:

```go
type PApplicationDelegate interface {
    // optional
    ApplicationWillResignActive(notification foundation.Notification)
    HasApplicationWillResignActive() bool

    // optional
    ApplicationDockMenu(sender Application) Menu
    HasApplicationDockMenu() bool

    // ... more methods
}
```

**Pattern:**
- Each optional method has a `Has{Method}()` companion
- Both method and check must be in interface

### Delegate Implementation Builder

```go
type ApplicationDelegate struct {
    _ApplicationWillResignActive func(notification foundation.Notification)
    _ApplicationDockMenu         func(sender Application) Menu
    // ... private function fields
}

func (di *ApplicationDelegate) HasApplicationWillResignActive() bool {
    return di._ApplicationWillResignActive != nil
}

func (di *ApplicationDelegate) SetApplicationWillResignActive(
    f func(notification foundation.Notification)) {
    di._ApplicationWillResignActive = f
}

func (di *ApplicationDelegate) ApplicationWillResignActive(
    notification foundation.Notification) {
    di._ApplicationWillResignActive(notification)
}
```

**Usage Pattern:**

```go
delegate := &appkit.ApplicationDelegate{}
delegate.SetApplicationDidFinishLaunching(func(notification foundation.Notification) {
    // Handle app launch
})
app.SetDelegate(delegate)
```

### Concrete Protocol Object

```go
type ApplicationDelegateObject struct {
    objc.Object
}

func (a_ ApplicationDelegateObject) HasApplicationWillResignActive() bool {
    return a_.RespondsToSelector(objc.Sel("applicationWillResignActive:"))
}

func (a_ ApplicationDelegateObject) ApplicationWillResignActive(
    notification foundation.Notification) {
    objc.Call[objc.Void](a_, objc.Sel("applicationWillResignActive:"), notification)
}
```

**Purpose:**
- Wraps existing Objective-C delegate objects
- Checks selector support via `RespondsToSelector`
- Directly calls Objective-C methods

## Objective-C Runtime Integration

### The objc Package

Core runtime integration in `/objc/` provides:

1. **Call System** (`call.go`):
```go
func Call[T any](o Handle, selector Selector, params ...any) T
```

2. **Type Conversions**:
   - Go string ↔ NSString*
   - Go []byte ↔ NSData*
   - Go []T ↔ NSArray*
   - Go map ↔ NSDictionary*
   - Go func ↔ Objective-C block

3. **Runtime Functions** (`base.go`):
```go
objc_msgSend           // Primary message send
objc_msgSend_stret     // Struct return (x86_64)
objc_msgSend_fpret     // Float return (x86_64)
objc_getClass          // Get class object
sel_registerName       // Register selector
```

### purego Integration

DarwinKit builds on [ebitengine/purego](https://github.com/ebitengine/purego):

```go
import "github.com/ebitengine/purego"

// Register runtime function
purego.RegisterLibFunc(&objc_getClass, libSystem, "objc_getClass")

// Create callback for blocks
callback := purego.NewCallback(goFunc)
```

**Benefits:**
- No CGO required
- Pure Go implementation
- Cross-platform support (x86_64, ARM64)

### Handle Interface

All Objective-C objects implement the Handle interface:

```go
type Handle interface {
    Ptr() unsafe.Pointer
}
```

**Implementations:**
- `objc.Object` - Base object type
- `objc.Class` - Class object type
- `objc.Selector` - Method selector type
- All generated classes (Button, Window, etc.)

### Memory Management

```go
// Retain/Release
func (o Object) Retain() Object {
    rv := objc.Call[Object](o, objc.Sel("retain"))
    return rv
}

func (o Object) Release() {
    objc.Call[objc.Void](o, objc.Sel("release"))
}

func (o Object) Autorelease() Object {
    rv := objc.Call[Object](o, objc.Sel("autorelease"))
    return rv
}

// Reference counting
func (o Object) RetainCount() uint {
    rv := objc.Call[uint](o, objc.Sel("retainCount"))
    return rv
}
```

## Best Practices

### 1. Use Interface Types for Parameters

Always use interface types (I-prefixed) for method parameters:

```go
// Good
func (w_ Window) SetContentView(value IView) {
    objc.Call[objc.Void](w_, objc.Sel("setContentView:"), value)
}

// Avoid
func (w_ Window) SetContentView(value View) { // Don't use concrete type
    objc.Call[objc.Void](w_, objc.Sel("setContentView:"), value)
}
```

### 2. Provide Convenience Constructors

Always provide both class method and module-level function:

```go
// Class method
func (bc _ButtonClass) ButtonWithTitle(title string) Button {
    return objc.Call[Button](bc, objc.Sel("buttonWithTitle:"), title)
}

// Module-level convenience
func Button_ButtonWithTitle(title string) Button {
    return ButtonClass.ButtonWithTitle(title)
}
```

### 3. Embed Parent Types

Structs should embed their parent:

```go
type Button struct {
    Control  // Embed parent
}

type Control struct {
    View  // Embed grandparent
}
```

### 4. Implement From Constructor

Every class needs a From constructor:

```go
func ButtonFrom(ptr unsafe.Pointer) Button {
    return Button{
        Control: ControlFrom(ptr),  // Chain to parent
    }
}
```

### 5. Use Type-Safe objc.Call

Always specify the return type:

```go
// Good
rv := objc.Call[Button](bc, objc.Sel("alloc"))

// Avoid
rv := objc.Call(bc, objc.Sel("alloc"))  // Type inference not explicit
```

## Summary

DarwinKit uses a highly structured, consistent pattern for Go bindings:

1. **One file per class** with predictable naming
2. **Dual class/interface design** for type safety and flexibility
3. **Comprehensive constructor patterns** (Alloc/Init, New, custom)
4. **Property accessors follow Objective-C naming**
5. **Protocol/delegate builder pattern** for callbacks
6. **Pure-Go runtime integration** via purego
7. **Automatic type conversion** for common types
8. **Memory management** exposed but with autorelease support

This architecture provides type-safe, idiomatic Go bindings while maintaining full compatibility with the Objective-C runtime.
